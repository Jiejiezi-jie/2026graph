# 路由标签规则与选择头实验总结

## 1. 实验目标

实验目标是为每道题选择一个 RAG 方法标签，训练一个选择头，根据问题自动路由到 `vector`、`lightrag` 或 `pathrag`。

官方评测结果来自 GraphRAG-Bench 的有效评测行。补回 `Medical-6b20ca96` 后，数据共 120 道题，按固定划分分为：

- 训练集：72 题
- 验证集：24 题
- 测试集：24 题

选择头使用问题文本或问题向量作为输入，标签来自三个方法在每道题上的 Answer Correctness、成本和规则筛选结果。

## 2. 标签规则

候选方法首先必须满足：

1. 方法 Answer Correctness 不低于设定阈值；
2. 方法 Answer Correctness 不低于本题最高正确率减去容差；
3. 在合格方法中选择输入 token 数与输出 token 数之和最低的方法作为银标。

如果没有方法合格，则使用本题正确率最高的方法作为回退标签，并标记为 `all_failed`。

本轮比较过以下规则：

| 规则 | 含义 |
|---|---|
| ≥0.50 | 正确率达到 0.50，合格方法中选择成本最低者 |
| ≥0.60，最高−0.05 | 正确率达到 0.60，且距离本题最高正确率不超过 0.05 |
| ≥0.60，最高−0.10 | 正确率达到 0.60，且距离本题最高正确率不超过 0.10 |
| ≥0.60，最高−0.15 | 正确率达到 0.60，且距离本题最高正确率不超过 0.15 |
| ≥0.60，最高−0.20 | 正确率达到 0.60，且距离本题最高正确率不超过 0.20 |

## 4. 最终采用的配置

最终采用：

```text
标签规则：Answer Correctness ≥ 0.60，且不低于本题最高正确率 − 0.10
合格方法：选择成本最低者
特征方法：TF-IDF
```

对应的选择头结果为：


### 三种固定方法与路由策略对比

缺失题补回前，23 道测试题上的汇总结果如下。该表保留用于对应原始实验截图，不作为完整测试集的最终数字。

| 方法 | Answer Correctness | Evidence Recall |
|---|---:|---:|
| Vector | 0.5876 | 0.6370 |
| LightRAG | 0.5346 | 0.5109 |
| PathRAG | 0.5603 | 0.4058 |
| Adaptive | **0.6196** | 0.5138 |
| Oracle | 0.6698 | 0.6080 |

补回 `Medical-6b20ca96` 后，完整 24 道测试题的最终结果为：

| 方法 | Answer Correctness | Evidence Recall |
|---|---:|---:|
| Vector | 0.5845 | 0.6521 |
| LightRAG | 0.5337 | 0.5313 |
| PathRAG | 0.5616 | 0.4306 |
| Adaptive | **0.6151** | 0.5340 |
| Oracle | 0.6666 | 0.6243 |

选择这一配置的主要原因：

1. 缺失题补回前，`≥0.60，最高−0.10 + TF-IDF` 的 23 题测试 Macro-F1 为 0.4960，是当时候选组合中最高的，因此冻结为最终方案；
2. 相比 BGE-M3，在同一标签规则下，TF-IDF 的测试准确率为 0.5652、Macro-F1 为 0.4960，均高于 BGE-M3 的 0.3913 和 0.3610；
3. 相比容差 0.05，容差 0.10 在原 23 题对比中使测试银标从 9/5/9 变为 11/4/8；补回的第 24 题按回退规则标为 PathRAG，因此最终分布为 11/4/9；
4. 容差扩大到 0.15 或 0.20 后，TF-IDF 测试 Macro-F1 分别下降到 0.3761 和 0.3644；
5. ≥0.50 规则虽然 BGE-M3 的测试准确率达到 0.6087，但标签分布高度偏向 `vector`，多数类准确率达到 0.6957，因此单看准确率会受到类别不平衡影响，Macro-F1 更低，不能作为更可靠的综合选择。

需要说明的是，最终选择参考了固定测试集上的对比结果，属于本轮实验中的经验性选择；如果要进行严格无偏的最终报告，应只使用验证集选择规则和特征方法，再将测试集作为一次性报告指标。

### 本轮固定方法与新路由结果

完整 24 题测试集上，使用 `>=0.60，最高-0.10 + BGE-M3` 新路由器的结果为：

| 方法 | Answer Correctness | Evidence Recall |
|---|---:|---:|
| Vector | 0.5845 | 0.6521 |
| LightRAG | 0.5337 | 0.5313 |
| PathRAG | 0.5815 | 0.5215 |
| Adaptive（新路由器） | **0.5946** | 0.5382 |
| Oracle | 0.7000 | 0.6007 |

Adaptive 的实际预测路由分布为 `Vector 10 / LightRAG 5 / PathRAG 9`；Oracle
银标路由分布为 `Vector 12 / LightRAG 1 / PathRAG 11`。这里的 Oracle 与项目既有
`official_analysis` 定义一致：按照同一阈值、容差和成本规则得到的逐题银标选择，而不是
简单取每题 Answer Correctness 最大的方法。若仅取每题最高 Answer Correctness，质量上限
为 0.7066，对应 Evidence Recall 为 0.6174。

与最好的固定正确性结果 Vector 相比，新 Adaptive 的 Answer Correctness 提高约 0.0101
（1.01 个百分点），但 Evidence Recall 下降约 0.1139。因此当前路由器带来了小幅答案质量
提升，但证据覆盖仍有明显改进空间。

### 耗时与复现性

- PathRAG 120 题生成：约 15 分 15 秒（包含一次从 GPU 0 到空闲 GPU 5 的断点切换）；
- 官方 120 题评分：约 7 分 17 秒；
- 12 组标签与分类器网格：约 11 秒；
- 从完整生成开始到首轮表格产出：约 22 分 57 秒；P0 预检和后续重复验证不计入该值；
- 实际只需一张 RTX 4090；主要耗时来自串行 DeepSeek API 调用，多占 GPU 不会线性加速；
- 离线重复运行时，银标、指标、测试预测和 JSON 文件完全一致。BGE-M3 的模型文件哈希一致；
  TF-IDF 的预测一致，但 `joblib` 序列化字节哈希会变化，不能把其文件哈希作为唯一复现判据。
